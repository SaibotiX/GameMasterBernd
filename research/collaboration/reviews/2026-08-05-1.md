# Collaboration review 1 — 2026-08-05 (the chronicler-round session)

Scope: one long session — batch-2 audit → maintainer's rulings → chronicler
round implemented → scrying-glass anonymity fix → batch 3 run and audited.
The baseline review; every class is NEW by definition.

## Verdict in one paragraph
A top-tier session, and the reasons are structural, not lucky: the
maintainer's pre-built process (CS-1) caught the one real conflict of the
day, and their ruling style (CS-2) let a 14-item decree turn into shipped,
verified code in one sitting. The improvement targets are all small
message-craft habits, not judgment: number the items, lead with intent,
attach one concrete failure to flakiness reports. Focus for next session:
CI-1 (numbered rulings) — it is the cheapest habit with the biggest
completeness payoff.

## Findings (SBI: situation → behavior → impact)

### CS-1 · Decision infrastructure before the work — the session's spine
- **S:** /thoughts click-to-expand requested; a 2026-08-03 decision said
  "no mouse, hotkey idiom." **B:** the maintainer had long since bound
  every session to check registries before adopting anything. **I:** the
  conflict surfaced as a ⚠ DEVIATION with a dated ruling instead of a
  silent contradiction; later, a fresh session could reconstruct the whole
  project state from the repo alone.

### CS-2 · Delegation with deviation permission — the mega-ruling
- **S:** the create-then-narrate pipeline proposal. **B:** "first analize
  if this workflow is even possible and if it would solve problems instead
  of adding new ones… you may do as fits best" — and on never-ask, they
  flagged their own idea's flaw ("This turns out one flaw…"). **I:** the
  pipeline landed in its sound form (ordering law + sweep) instead of
  being blindly built or quietly dropped; the never-ask law got the
  prophetic-register design instead of an impossible literal one.

### CS-3 · Evidence with the observation
- **S:** the Bernd and GM observations. **B:** verbatim GM quote, session
  id 019fcb81…, the exact ledger path, "I asked multiple times, it only
  ever gave u3." **I:** the u1 question was settled definitively — and the
  answer ("the GM was right; u1–u2 are pi bookkeeping") was only findable
  because the report was precise.

### CS-4 · Explicit scope bounding
- **S:** ruling on the batch-2 report. **B:** "Everything else in the
  report we let be… I would like to keep track of the things we found."
  **I:** four findings stayed deliberately unfixed instead of bloating the
  round — and the report-tally tool exists because tracking was named as
  the alternative to fixing.

### CS-5 · Asking instead of nodding
- **S:** "what is RITE"; "I think the reports are not saved? Can you
  check?" **B:** asked for explanation and verification rather than
  assuming. **I:** a folder confusion died in one turn instead of becoming
  distrust of the process.

### CI-1 · Unnumbered multi-item rulings — NEW, the next focus
- **S:** the main ruling message. **B:** ~14 concerns (rulings, new bugs,
  questions, feature specs) in flowing prose, un-numbered. **I:** it
  worked because the session tracked items in a task list — but the
  maintainer had no checklist to verify completeness against, and a less
  careful session could drop an item silently. **Practice:** number the
  items; expect the reply to answer by number.

### CI-2 · Mechanism before intent — NEW
- **S:** the /thoughts specification. **B:** detailed click-to-expand
  mechanics; the intent (thoughts out of the way, recoverable, persistent)
  had to be reverse-engineered when pi's TUI turned out to have no mouse
  support at all. **I:** deliverable intent briefly hostage to an
  impossible mechanism; resolved only because deviation was surfaced.
  Notably the maintainer DID grant mechanism-freedom elsewhere — the habit
  exists, it just wasn't attached to the UI spec.

### CI-3 · Flakiness reported without an instance — NEW
- **S:** "the text, image and video gathering out of the web is prone to
  errors." **B:** true, actionable direction — but no failing query,
  time, or message. **I:** the fix was designed from re-analysis and
  fresh probes rather than verified against the maintainer's actual
  failures; a single captured instance would have closed that loop.

### CI-4 · Missing search-path and budget context — NEW
- **S:** "I don't find them [the reports]" (no where-I-looked); "please
  start with Batch 3" (no scale/cost expectation). **B/I:** both resolved
  by inference (folder guess was right; 6 sittings at ~$4 was accepted) —
  but both were guesses made on the maintainer's behalf.
